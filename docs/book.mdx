`/app/settings/message-template` redirects to Settings. `/app/recalls` redirects to Calendar.

Shell nav is Dashboard, Clients, Calendar, Settings. The mark in the shell is the salon name.

## Recall date

From `src/lib/schedule.ts`:

- **Lapse** = last visit + lifespan weeks
- **Recall** = lapse minus lead: on the day (0), 1 day before (1), or 1 week before (7)

Entering a new last visit resets Contact to not yet contacted and Response to not yet booked (`src/lib/db.ts`).

## Follow-up vs the bell

**Follow-up** (Clients segment) is status only — `isOnDueList`:

- Contact is `not_yet_contacted` or `contacted_unreachable`
- and Response is `not_yet_booked`

Recall date does not decide Follow-up.

**Bell**, **Due today**, and **Overdue** use that same status rule **and** the recall date: today, or already past. The bell is overdue count + due-today count.

Contact labels: Not yet contacted, Contacted but unreachable, Contacted.  
Response labels: Not yet responded, Acknowledged, Booked, Declined.

## Messages

SMS, WhatsApp, and Call on the recall card open this device (`sms:`, `wa.me`, `tel:`). There is no NewRecall message server.

Wording is `DEFAULT_MESSAGE_TEMPLATE` in `src/lib/messageTemplate.ts`. Guest bookings switch `whose_visit` and `book_who`. There is no Settings editor. `/app/settings/message-template` is a redirect.

## Settings and backup

- Salon name (default **Your salon**), owner-only
- Staff invites (owner). Staff share the book and do not create a salon or Paystack customer
- Service types catalog (Postgres)
- Backup: export/import JSON. Import replaces the salon book after confirm
- Subscription: plan, trial/next payment, Manage subscription (Paystack portal, owner-only). Hidden when the paywall is bypassed
- Alerts: Due today and Overdue switches (default off, per user / device)

The backup file includes salon name, clients, optional catalog, and a copy of the code template. Import does not add a template editor; the running app still uses the code constant.

`useClients` loads from Supabase and stays live with `postgres_changes` on `clients` and `notes` filtered by `salon_id`.
